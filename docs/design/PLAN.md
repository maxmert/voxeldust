# Voxeldust Greenfield Rebuild — Transfer-First MMO Foundation

## Context

The current Voxeldust (`ecs-system` branch, ~150k LOC) is chronically broken in exactly one place: **passing players between shards**. A deep multi-agent audit (11 agents over the codebase + the open-source landscape, then 18 design/attack/hardening agents) established why, with evidence:

**Bugs cluster in transfer machinery, not features.** Of 77 commits past main, 32% are fix/WIP/diagnostic and 26% transfer-specific — almost all in three god-files (`ship-shard/main.rs` 9.6k LOC re-fixed 13×, `system-shard/main.rs` 7.3k re-fixed 15×, `planet-shard/main.rs` 3.7k re-fixed 11×). Feature commits land once and rarely return.

**Root causes (all architectural, none fixable in place):**
- **R1** No owner of the transfer lifecycle; no timeouts/retry/rollback anywhere; `HandoffPending` inserted but *never removed* — one lost ack permanently wedges a player.
- **R2** Client re-homes its own connections (observer promotion): arbitrary eviction of the about-to-promote connection, UDP-to-session IP-matching heuristic silently dropping all input ("stuck but camera rotates"), ordering invariants enforced only by comments.
- **R3** Spawn-on-promote ("create + hope") instead of pre-existing ghosts.
- **R4** `PlayerHandoff` god-struct: ~12 mutually-exclusive Options for 6+ transition types.
- **R5** Zero behavioral tests *possible*: bin-only shard crates, socket-coupled harness, hard-realtime ticks, no fault injection. Transfer-testing capability: 1/10. Feedback loop = rebuild k3d → fly client → grep logs.
- **R6** Coordinate-frame reconstruction duplicated per shard; ~110 km/s orbital velocity → ms of clock skew = km of spawn error (documented 1.8 km residual).
- **R7** Forgeable identity: session token = SipHash of `SystemTime::now()`, validated by no one, triple-overloaded as identity + promotion key + handoff correlation.
- **R8** Visibility via lossy 1Hz digests + hand-tuned 3s/10s timeouts.
- **R9** Fire-and-forget `try_send` for all inter-shard control messages.
- **R10** No transfer correlation IDs; debugging = add log lines, deploy, strip them.

Verified foundation gaps: planet block edits **never persisted** (builds vanish on restart), `universe_epoch_ms` resets on orchestrator restart (orbital clock desync), no protocol versioning, inter-shard QUIC accepts any cert, `PlayerHandoff` spoofable.

**Open-source verdict (June 2026):** *No* open-source library implements cross-process authority handoff in Rust (lightyear, bevy_replicon, naia, renet, SpacetimeDB, Nakama — all checked; the 10k-player Rust projects Hyperion/Valence deliberately avoid sharding game logic). **Voxeldust must own the transfer layer.** The *patterns* are proven in production and this design builds on them: gateway-owns-the-connection (EVE Proxy, SC Gateway), authority bit + ghosts in overlap bands (SC, SpatialOS, Folia), two-phase handover with bounded forced resolution (Improbable patent US10878146B2), central ownership directory (MultiPaper), handoff-as-durable-saga. Library adoptions: keep quinn/bevy_ecs/rapier3d/redb/wgpu/brahe/noise(pinned)/binary-greedy-meshing; **postcard** replaces FlatBuffers (v1, one serializer; bitcode bit reserved); Agones/NATS evaluated and deferred (custom orchestrator is sound; no broker needed at this scale).

## User Decisions (locked)

1. **Total greenfield** — new empty workspace; old repo is reference/spec only (port proven *pure math* with its tests; re-design all structure).
2. **Gateway owns the connection** — client holds ONE persistent QUIC connection for its whole session; transfers are server-side route swaps the client transport never observes.
3. **All transitions seamless** — ship↔planet, ship↔EVA, planet↔space, system↔galaxy warp (provisioning-aware) — full ghost + two-phase machinery. No reconnects, no loading screens.
4. **MMO-grade durability from day one** — signed identity, persisted universe epoch, durable transfer saga surviving crashes mid-transfer, player checkpoints, per-realm block-edit delta store.

Binding standards (project memory): no magic numbers (world/sim params seed-derived; entity props per-entity; *operational* params live in ONE reviewed config struct — `TransportTuning`/`TransferTuning` — never inline literals), NO client-side prediction (interpolation on a 100–150 ms buffer), players physically collide, shard-agnostic block logic, deterministic generation, production-grade error handling.

## Hard Architectural Rules (user-mandated, designed + adversarially hardened)

**HR1 — No data leaks between shards.** A shard's ECS world, rapier context, and redb store are PRIVATE. Two closed type taxonomies are the only egress, neither with an escape hatch: (a) `InterShardFlow` (shard↔shard / shard↔orchestrator): `Ghost | Transfer | Directory | BlockEdit | Coupling | Signal` — one reviewed file in `wire`; (b) the connection-plane client families (`ControlMsg | BulkMsg | EventMsg | SnapshotDatagram | InputDatagram`). Enforcement is structural: the `InterShardFlow` encoder is the sole producer of shard-bound bytes through `Transport::send`; crate-graph isolation (no edge reaches another shard's World); clippy disallowed-methods; a conformance test asserting *effect classes* (side-effecting arms MUST carry `(TransferId, step_id)` + acks; fire-and-forget arms MUST be `EffectFree` — a marker trait an authority-gating payload cannot implement). Simulation cross-feeds are **typed `CouplingPort`s** (effect-free, latest-wins): the user's canonical example is `ShipThrustPort` — ship shard aggregates `ShipOutputs{thrust, torque, mass, com…}` → current hull-host shard integrates the hull rigid body → `HullPose` feedback; the client subscribes to ship + host + planet-in-SOI and composites all of it. Declared degraded modes per port (host crash ⇒ hull coasts ballistic closed-form; ship crash ⇒ hold-last-N-then-decay; **normal hull-host transfer ⇒ hold-last-thrust** via `last_ship_outputs` carried in the saga handoff state — no thrust dropout at 3g across an SOI). Discrete authority-gating events (e.g. dock clamps) are NOT couplings — they are Transfers through the saga, by construction. Gameplay-level cross-shard data rides the **Signal system** (`SignalScope ∈ Local | ShortRange | LongRange | Radio{freq}` via the Galaxy Relay with leased subscribers; rate-limited, HMAC-granted, fence-stamped, idempotent where durable).

**HR2 — Generic transfer: ANY object crosses shards.** One `TransferableKind` registry (`EntityKind` → `KindDef{DurabilityClass, GhostPolicy, ContinuityModel, LossBudget, blob_schema}` + one trait impl: serialize/spawn/precondition/rebind_refs). Adding a kind within an existing (class, continuity, ghost) triple = 4 lines, zero new transfer code. State crosses as **TLV-framed typed blobs** (unknown tags skippable; per-kind version-floor handshake — the orchestrator refuses to route a Durable entity to a dest missing a required tag; decode-to-Default is BANNED for Durable kinds: hard abort, player stays alive on source). **Durability tiering on ONE machinery**: `Durable` (players, ships, named constructions — per-entity OwnerRecord, full saga WAL, full crash matrix, zero loss) vs `Transient` (bullets, debris, dropped blocks — explicitly-HELD `owned_transients` sets anchored to the realm-lease Fence, batched `TransientTransferBatch` envelopes, **batched durable `TransientGo` go-token** = the same orchestrator Fence-CAS commit point amortized to ~1 fsync/tick regardless of item count, declared loss budgets, never wedges). *(Integrator resolution: Charter A's go-token supersedes Charter B's zero-touch fire-and-forget — NO-UNILATERAL-COMMIT holds uniformly; the cost goal is preserved because tokens are per-batch, not per-item.)* Continuity per kind: `Frozen` (players/ships), `BallisticReadvance` (closed-form re-advance — debris/projectiles), `Guided` (rockets; four-way target resolution incl. the frozen/fence-stale-target case → honest ballistic degrade), `RealmAnchored` (dropped block → durable two-step `LandBlock` conversion keyed by `entity_id`, acked against `block_wal` before despawn). Damage across a transferring victim is serialized through the transfer barrier: `freeze_tick` is the cut; an `applied_damage` dedup set crosses with the entity — exactly one authoritative application.

**HR3 — One tooling for all shard types.** One transfer FSM, one envelope family, one Fence, one ghost transport, one registry, one commit point, one `node` lib, **ONE `shard` binary** — galaxy/system/planet/ship/station/asteroid are validated capability *configurations*, not codebases. `G-NO-SHARD-FORK` lint: no `match` on a shard-kind discriminant in feature code; geometry differences confined to `FrameSpace` impls.

**HR4 — Features implement-once, run-anywhere.** `ShardProfile` is a validated capability DAG (`FunctionalBlocksCap: VoxelRealmCap + SignalGraphCap`, …) built only via `ShardProfile::build()` — incoherent profiles fail loud at config load. All gameplay features are `sim` systems written against capability traits, registered identically for every NodeKind that satisfies them. The geometry seam is a **stateful `FrameSpace`** (`CartesianSpace` for ships/stations; `SphericalSpace` with a `SurfaceAnchor` + `reanchor()` and `AnchorGen` fencing for planets — stale-gen coordinates rejected, single-cluster-per-planet is a loud hard error, multi-cluster deferred); everything above it (62³ chunk addressing, greedy meshing, edit pipeline, gravity_dir) is shared write-once. Permanent CI gate **G-IDENTICAL**: every feature lands with `assert_feature_anywhere` passing the identical fixture on a Spherical AND a Cartesian profile (with one fixture forcing a reanchor), or it doesn't land.

**HR5 — 100% test coverage, real not theater.** "100%" is defined precisely: **100% LLVM region coverage AND 100% branch coverage on the Tier-A crates** (`sim`, `core`/`wire`, `connection-plane`, `node` lib, `harness`), enforced by `cargo llvm-cov --branch --fail-under-regions 100 --fail-under-functions 100` in a `just coverage` pre-merge gate (coverage runs on a pinned nightly — branch coverage and `#[coverage(off)]` are nightly-only as of 2026; product builds stay stable). Tier-B (`io-prod` quinn/redb adapters, bin shells) is covered by the real-binary process tier with merged child-process profiles (`show-env` + `LLVM_PROFILE_FILE` `%p-%m%c` — `%c` continuous mode is mandatory because the harness SIGKILLs processes) at a **ratcheted floor** (honestly never 100%: a SIGKILL can lose the final counter flush). WGSL shaders / egui draw / winit glue are uncoverable by any coverage tool — their substitute is the HR6 visual harness. Exemptions only via `#[cfg_attr(coverage_nightly, coverage(off))]` on provably-unreachable code or a reviewed `coverage-exemptions.toml` with per-entry justification; exemption count is a tracked metric; an exemption on reachable logic is a review-rejectable defect. A subsystem is "done" only at 100% region+branch with zero unjustified exemptions.

**HR6 — Claude-operable E2E testing of client + rendering.** The client ships a **dev-control harness** so the AI agent can run, drive, observe, and fix the real client end-to-end: (a) a localhost-only control channel (JSON-lines TCP on `9100+slot`, fronted by a `vdctl` CLI driven from Bash) compiled only under `#[cfg(feature = "dev-control")]` — absent from release binaries, not merely disabled; (b) **input injection as the logged-in user**: dev commands write the same input-state resource the keyboard/mouse systems write, upstream of the `InputDatagram` assembler — agent input is byte-identical to real input, never synthetic OS events; (c) primitives: `press/move/look/action`, closed-loop `walk-to`/`look-at`/`wait-until '<predicate>'`, `state` (structured JSON from the client's *decoded delivered* world view — same honesty rule as the WireMonitor), gameplay-action shortcuts (`board-ship`, `warp-to`) plus an explicitly-named `dev-teleport` for setup; (d) **capture via in-engine wgpu readback** (post-egui composite, 256-byte row padding, `map_async`+`poll`, async off the present path — not OS screen capture, which needs macOS TCC permissions an agent can't click): `screenshot [--at-tick T]` (deterministic captured state) and `record --fps N --secs D` (reduced-rate frame sequence → ffmpeg/PNG); (e) every run lands in `runs/<ts>__<scenario>/` with a manifest aligning each frame to its tick and its `state` dump, so agent diagnosis is reproducible. The agent loop: `dev-cluster.sh up` → N clients with `--dev-control` → bash scenario of `vdctl` commands → Claude reads the PNGs + manifests → diagnoses → fixes → reruns. Multi-client scenarios visually verify cross-shard compositing (client2 screenshots client1's ship crossing a boundary). **Division of labor:** the WireMonitor proves delivered bytes; HR6 proves *rendering* (shaders, z-fighting, lighting, transitions, HUD) — the only coverage for what HR5 excludes. Visual regression = automated structural assertions on the readback (no-magenta/no-NaN sentinels, content-present %, luminance-histogram bounds, HUD-anchor non-empty, static-scene frame stability) as the gate + Claude semantic review as the exploratory layer; golden-pixel diffs only for AA-off synthetic scenes.

## Unified Architecture

(All cross-design conflicts resolved by the integration pass; resolutions baked in below.)

### Topology

```
CLIENT ══ ONE persistent QUIC conn ══ GATEWAY ──(mTLS QUIC pool, K conns/pair)── SHARDS (ship/planet/system/galaxy)
                                         │                                          │ bevy_ecs + rapier3d
                                         │ route table (lock-free ArcSwap)          │ Owned/Ghost/Frozen entities
                                         │                                          │ per-Realm redb (realm owner only)
                              ORCHESTRATOR (directory + saga + clock + ephemeris)   │
                              AUTH service (Argon2id off the saga-timer threads)    └── shard↔shard GhostDelta datagrams
```

- Client never re-homes, never learns a shard IP, never participates in a transfer. The old client `ConnectionMode`/observer machinery does not exist.
- Server-side routing is always by in-frame `SessionId` (+ fence), **never** by source address.
- Two orthogonal replication planes: shard↔shard GhostDelta (feeds neighbor's kinematic colliders + its snapshots) and shard→gateway→client snapshots. The gateway forwards snapshots only; it is never a ghost-pose router. A ghost is just another entity in its host shard's snapshot — the client never knows an entity is cross-shard.

### The fence — ONE linearizability primitive

`Fence(u64)` per directory key, bumped on every ownership change, never reused. (Collapses the designs' `session_gen`/`lease_epoch`/`version` into one mechanism.)
1. Every authoritative action and inter-process message carries the fence it was issued under; receivers reject `fence < highest_seen`.
2. **The directory CAS is the single commit point.** Authority is derived from the directory, never from a peer notification.
3. COMMIT and ABORT are each a CAS on the same fence — mutually exclusive by construction; the loser no-ops.
4. Self-fence-before-grant: a node failing lease renewal hard-stops authority within `self_fence_grace`; the orchestrator reassigns only after `lease_ttl + max_self_fence_grace`. Lapsed lease ⇒ ownership loss **only when the orchestrator confirms the owner unreachable** — an orchestrator outage freezes recovery (existing routes keep working), never mass-orphans.
5. The gateway validates the fence on every snapshot frame — a stale/partitioned old owner physically cannot affect the client.

### Ownership directory (orchestrator, redb)

Unified key space: `Session(session_id) | Entity(EntityId) | Realm(RealmId) | Ship(ShipId)` where `RealmId = planet_seed | system_seed | ship_id`. One record shape: `OwnerRecord { authority: ShardRef|GatewayRef, fence, lease_expires, in_transfer: Option<TransferId> }` (+ `resume_nonce` on Session keys). Writes linearizable (single writer); caches are hints — authority decisions pull through. `in_transfer` is enforced: blocks concurrent sagas and ghost-despawn mid-transfer. Identity triple: `AccountId` (durable principal) / `SessionId` (connection-session) / `EntityId(u128){kind,mint_shard,seq,rand}` (the simulated thing; a session may own several). EntityId is NOT embedded in credentials; the directory maps session→player→owned entities.

### Transfer saga (the heart)

Lives **in the orchestrator**: pure FSM crate (`fn step(State, Event) -> (State, Vec<Action>)`, proptested) wrapped with redb persistence + at-least-once delivery. One `TransferId` (u128) correlates everything (messages, spans, idempotency `(TransferId, step_id)`, the post-mortem WAL). Per-Entity/Ship key serialization: at most one saga per key.

Gateway-facing command API (contract-tested seam): `PrepareSubscribe → RequestCut → FreezeSource → CommitAuthority → ThawSource(compensator) → AbortTransfer → ReleaseSubscribe`, every phase separately acked and compensatable. Internal FSM: `PREPARE → FLUSH → FENCE_DEMOTE → PROMOTE → CLEANUP`, with `AWAIT_PROVISION` before PREPARE for warp.

The input cut: **client-emitted in-band `CUT_MARKER`** on the seq-ordered INPUT datagram flow (triple-sent + confirmed on reliable CONTROL). Gateway routes `seq ≤ marker → source`, `seq > marker → dest buffer` (applied after commit). Durable per-txn seq-range interval map in the directory: every seq range owned by exactly one shard, forever, reload-from-directory on reconnect. (Resolves the dual-cut conflict: no source-side input ring; `InputGap` only as the rare forced-resolution signal.)

Commit pipeline (resolves the 3-way COMMIT conflict): dest ghost fresh + spatial preconditions ok (`PrepareResult::Rejected{spatial_reason}` is typed — hull-trap class aborts with feedback) → cut confirmed → source frozen+drained → **directory CAS (fence+1) = the commit** → notify gateway → gateway atomic `route.store` (single Arc swap, wait-free hot path) → ordered Demote(ack) before Promote → dest pulls directory head, applies frozen state, re-advances analytically → release after dest acks delivered-to-all-observers AND entity left the overlap band (event-driven demotion — no magic tick counts). Bounded forced resolution = FENCE-THEN-FORCE: fence first (gateway drops stale-fence frames), distinguish crash-vs-slow via lease, bounded acknowledged gap. **Every abort path ends with the player alive, authoritative somewhere, consistent — source authority is retained until dest's Committed ack.**

Warp/provisioning: child saga (`ProvisionIntent{node_id = derive(TransferId, epoch)}` persisted **before** spawn; spawn idempotent; freshly-provisioned pod asks "am I still wanted for saga T?" and self-terminates if aborted — no zombie owners; durable de-provision compensation; idle-GC). ProvisionProgress streams to the client as `TransferCosmetic{warp_progress}` — the shrink-to-a-dot visual stretches to ETA.

Ship compound transfer: ship exterior authority transfers via the standard saga on the `Ship` key; interior world stays ship-shard-owned throughout (passengers feel nothing). Passengers are `ChildOf(ShipId)` re-parented in ONE redb txn (kept within one region — the future directory-partitioning seam). Ship + children stream as ONE versioned bundle so external observers never see a passenger teleport relative to the hull.

### Ghosts & overlap bands

Ghosts exist for the **whole time** an entity is in a geometric overlap band (not just during transfers) — kinematic colliders fed by GhostDelta datagrams, **never independently integrating physics** (resolves the collide-vs-frozen conflict; satisfies players-must-collide across boundaries). Bands per class (`planet_soi` Hill-sphere vs `system_soi` luminosity — two *named, separately tested* functions), velocity-scaled width (`≥ v_rel·dt·K_safety`, swept-segment crossing detection — no tunneling at 5.5 km/tick), enter>exit hysteresis, sustained-inward `N_entry` ticks to commit, `K_dwell` cooldown + `transfer_pingpong` alert metric. GhostSpawn/Despawn on the reliable acked control stream; despawn refused while `in_transfer=Some`; deltas fenced by tick. Cross-shard visibility = the same machinery (the lossy 1Hz digest system is dead). Cross-shard block edits are **forwarded to the realm owner** (single-writer redb), never written locally.

### Connection plane & wire

| Channel | QUIC object | Reliability | Carries |
|---|---|---|---|
| CONTROL | 1 bidi stream | reliable | session lifecycle, auth, SubscriptionOpened/Closing, AuthorityChanged, ReferenceFrameDef, RequestCut/CutConfirmed, TransferCosmetic/Rejected |
| INPUT | datagrams | unreliable, seq | 20Hz InputFrame (latest-wins) + CUT_MARKER; *discrete world-mutating actions go reliable with their own seq+ack (v1.1)* |
| BULK[sub] | uni per subscription | reliable, RTT-paced | chunk snapshots/deltas, configs, grants |
| EVENTS[sub] | uni per subscription | reliable | damage/destroyed/chat — opened causally after SubscriptionOpened (X1) |
| SNAPSHOT | datagrams | unreliable | 20Hz per-sub frames tagged `sub_id` (monotonic, never reused) + `frame_id` + `source_tick` |

postcard everywhere v1 (codec flag bit reserved for bitcode; FlatBuffers gone). `Hello{proto_major/minor}` negotiation; rolling upgrades drain old connections. Entity-state blobs are TLV-framed (HR2) with the per-kind version-floor handshake. The `InterShardFlow` taxonomy freezes **incrementally** (the reviewed file exists from P0; arms land with their first consumer: Ghost/Transfer-Durable/Directory at P0, BlockEdit + Transfer-Transient at P3/P6, Coupling at P8, Signal at P9 — the closed-set guarantee is a per-release conformance gate, not a day-one empty freeze). Hot path is lock-free (`ArcSwap<RouteSnapshot>` + atomics; no lock across awaited sends). BULK paced from live quinn RTT so a 4 MB chunk burst can't starve snapshot datagrams (CI-asserted delivery ratio). Datagram budget asserted ≥ negotiated `max_datagram_size` at startup (k3d VXLAN clamp fails loud). Gateways soft-stateful + horizontally scalable: HMAC ResumeTicket with single-use directory nonce, adoption via Session-fence CAS (old gateway self-fences), in-flight transfers recovered solely through the saga. Client net module is ~one task (~10× smaller than the old `connection.rs`).

### Identity & trust

Login: Ed25519 `login_ticket` validated by gateway against the auth service. In-session/resume: HMAC tickets, **gateway-only validation — shards never see tickets**; shards accept a `session_id` only over mTLS from the directory-current authority at a valid fence AND saga-attested for that shard. Day-1 trust: ONE static cluster cert (PSK) for all inter-process mTLS; peer identity cross-checked against the directory (CA + per-shard SPIFFE certs deferred to a real multi-tenant boundary). Key rotation (renewals mint fresh tickets), revocation epoch (bans bite mid-session), conn-binding (replay on another connection rejected). Argon2id in the separate auth service.

### Time & coordinate frames

**No globally-synchronized simulation tick** (the harness exercises tick-skew deliberately). The shared quantity is the orchestrator's **DurableUniverseClock**: write-ahead-reserved tick ceiling (restart resumes at the ceiling — time never rewinds), monotonic clamp at every shard, epoch persisted at genesis. Every persisted record carries `universe_epoch_id + schema_version`; mismatch ⇒ discard/abort (fail-safe); `dev-cluster.sh` gets atomic wipe-all-stores.

Celestial/frame math is **closed-form `f(seed, universe_tick)`** (Category A — analytic, bit-deterministic, no per-tick accumulation); rapier state is Category C — checkpoint-carried, **never re-simulated on another host**; free-fall re-advance uses the closed-form ballistic solve. Frames travel as time-parameterized functions (`ReferenceFrameDef`/`StampedPose{frame_ref, pos, vel, orient, universe_tick}` — one shared type); the client evaluates frames at its render tick. The **source shard computes the destination pose** and ships it (dest sanity-bounds it against the orchestrator's Ephemeris Authority — authority never depends on cross-binary float reproducibility). Galaxy frame = integer light-year cells + f64 offsets. Every cross-shard message carries the sender's `source_tick`.

### Persistence (per-realm, MMO-grade)

All durable world state keyed by **RealmId** on persistent volumes (never shard_id — the old `/tmp/…{shard_id}.redb` data-loss bug), single-writer enforced via the directory's Realm owner. Tables per realm owner: `block_wal` (5-byte dedup-to-final edits, sorted drain for determinism, ~250 ms batched fsync off-tick) + `chunk_snapshot` with the **3-step durable checkpoint** (write snapshot+fsync → record checkpoint LSN+fsync → prune strictly ≤ LSN; replay idempotent) + `player_ckpt` (hot tier 1 s coalesced/1 fsync, warm tier on-change; includes the durable freeze marker so an aborted transfer is completable even if the source died) + `applied_steps (TransferId, step_id)` idempotency in the same txn as side effects + `config_state`/`grants`/`ship_design`/`meta`. Orchestrator: `directory`, `transfer_saga` (persist only at PREPARE-ack + COMMIT-CAS; group-commit; separate redb file from directory), `saga_tombstones` (terminal cids block late dup PREPAREs), `universe`, `provision_intents`. Auth: `accounts`, `session_keys`. Orchestrator restart **resumes** sagas (re-drive idempotently to terminal) — blanket-abort is only a temporary staging simplification.

### Glossary (binding vocabulary)
