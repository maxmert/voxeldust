# CORRECTED DESIGN OF RECORD — R-6d4 (reachable-now)

## Global must-fix that reshapes the slice
The B4 pin **cannot be mutation-sensitive to `notify_waiters()` without a one-line production change** to the LANDED async loop (store.rs:208). The original design's NON-GOAL ("no change to landed mechanism code") is incompatible with B4's stated value. **Decision: make the minimal mechanism change** — it is a genuine correctness sharpening (death should short-circuit, not wait a full poll), it is the ONLY way to close the wf_75a225d0 gap R-6d4 exists for, and it keeps the sync sibling honest too. This is surfaced as a scope escalation to the mechanism owner in the slice, not smuggled.

### R-6d4-M (mechanism, one-line, lands FIRST as its own reviewable commit)
In `wait_durable_through_async` add a death short-circuit in the `Ok(())` arm (store.rs:208): after a notify-driven wake, if `last_durable < seq && !writer_alive` → panic immediately (same message as store.rs:216, hoisted to a monomorphic helper `fn writer_died_panic(seq) -> !` so both arms call it — HR5(a), branchless generic discipline N/A here but keep one panic site). Mirror it in `park_until_durable` (store.rs:342-354): re-check `is_writer_dead()` after every wake, not only on `res.timed_out()`. Effect: a live `notify_waiters()` (death) delivers the panic in ~0; a neutered one falls to the full `WRITER_WAIT_POLL` timeout. This CREATES the prompt-wake gap B3/B4 assert against. No prod behavior change on the happy path (durable bump still fast-returns via the `last_durable >= seq` recheck). Files: store.rs. Coverage: Tier-A (the new short-circuit branch is covered by B4).
