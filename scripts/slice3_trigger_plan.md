===== MUST-FIX #1 (FATAL): should_commit REDESIGNED — membership-dwell rising edge, swept only for direction/anti-tunnel =====
New monomorphic fn in geometry.rs (after resolve_winner :469). ALL branching here (caller is a branchless shim, HR5(a)).

`pub fn should_commit(prev_cell: I64Vec3, cur_cell: I64Vec3, swept: ShellCrossing, now_member: bool, inward_ticks: u32, since_commit: Option<u32>, tuning: &BoundaryTuning) -> Option<Direction>`

The DECOUPLING (the fix): swept classifies DIRECTION + anti-tunnel ONLY; the commit is a LEVEL/EDGE test on the membership dwell counter, evaluated on the tick the dwell MATURES (which for a fast crosser is a StaysInside tick, NOT the swept==Inward tick). Logic, in order:
1. COOLDOWN (Option, MUST-FIX #4): `if let Some(sc)=since_commit { if sc < tuning.k_dwell { return None; } }` — None means no prior commit ⇒ cooldown inert (never the TickId(0) sentinel).
2. INTEGER-CELL GATE (determinism): `let cross_cell = prev_cell != cur_cell;` — through P3 both are I64Vec3::ZERO so cross_cell==false always (a covered straight-line no-op that never changes the outcome today), the region+decision exist for P4/P5. The MUST-FIX-#5 fixture plants distinct non-zero cells so the DECISION flips. f64 (membership/swept) decides sub-cell/direction; the integer compare gates cross-cell. Bind it into the arms below so it is not dead.
3. OUTWARD / ThroughAndBack — IMMEDIATE on the swept edge (leaving is not dwelled): `match swept { ShellCrossing::Outward | ShellCrossing::ThroughAndBack => return Some(Direction::Outward), _ => {} }`. (ThroughAndBack ends outside → terminal side is Outward.)
4. INWARD — a RISING EDGE on the dwell maturity, NOT gated on swept: `if now_member && inward_ticks == tuning.n_entry { return Some(Direction::Inward); }`. `==` (strict rising edge, exactly one commit as the counter passes n_entry — the caller pre-increments, so inward_ticks==n_entry is hit on exactly one tick), `now_member` guards a spurious fire if the counter is stale. This is evaluated on EVERY tick (including StaysInside), so a fast crosser that entered the annulus and is now deep inside still commits when its consecutive-membership count reaches n_entry. swept==Inward is NOT required.
5. else `None`.
Note the cross_cell gate: through P3 it is inert; the fixture drives a case where prev_cell!=cur_cell must be true for the inward commit to be authorized (the P4/P5 semantic — a commit only when the coarse cell relationship is settled). Concretely: `if now_member && inward_ticks == tuning.n_entry && (!cross_cell_blocks(cross_cell)) { Some(Inward) }` where cross_cell_blocks is a straight-line helper returning false today (never blocks) but whose region+arg exist. Keep it as a covered no-op that the fixture exercises both ways.
TRUTH TABLE STRUCTURE (MUST-FIX #10, avoid the uncoverable cross-product): enumerate ARM-STRUCTURED, not naive cross. For StaysOutside → always None (early after cooldown/cell, before any dwell read — but note now_member==false there so arm-4 is naturally false). For Inward-commit coverage vary inward_ticks {n_entry-1, n_entry, n_entry+1} × now_member{t,f} on the StaysInside arm (where a fast crosser actually matures). For Outward/ThroughAndBack the swept arm returns immediately (inward_ticks unread). Split every assert!(a&&b); assert_eq! on Option<Direction>, never matches!.
BoundaryTuning DEFAULT n_entry=3, k_dwell=5 (geometry.rs:427) is the tuning source; StubConfig gains `boundary: BoundaryTuning`, validated at register_stub_shard via BoundaryTuning::validate.
