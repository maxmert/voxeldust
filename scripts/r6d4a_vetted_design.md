## (1) MODEL — three pieces computed from independent sources of truth

**`ModelOutboxSink` (the code-under-test's sink; two-set RAM/disk crash model).**
Fields: `committed: BTreeMap<OutboxKey, Vec<u8>>` (durable; what `scan_all` returns, ascending), `staged: BTreeMap<OutboxKey, Option<Vec<u8>>>` (RAM; `Some`=retain, `None`=release; lost on crash), `durability: DurabilityHandle`.
Trait impl mirrors `NodeOutbox` (outbox.rs:237-300): `retain`→`staged.insert(k, Some(framed))` storing the envelope-stripped bytes `scan_all` yields; `release`→`staged.insert(k, None)`; `commit`→drain `staged` into `committed` last-write-wins (`Some`→insert, `None`→remove), clear staged; `scan_all`→`committed.iter().cloned().collect()` (ascending); `gc_below`→retain `key.incarnation >= inc`; `gc_replayed(keys)`→straight-line `for k in keys { committed.remove(k); }` (byte-identical to outbox.rs:281-287); `submit_barrier`→`if staged.is_empty() {None} else {Some((next_seq, durability.clone()))}`; `durability`→`durability.clone()`.

**`DedupLedger` (the REAL receiver oracle — MF-1/INV-1/INV-4).**
`struct DedupLedger { states: BTreeMap<(NodeId, MsgClass), RecvState>, delivered: BTreeSet<OutboxKey>, arrivals: usize }`.
`fn accept(&mut self, k: OutboxKey) -> bool`: fetch-or-default the `RecvState` for `(k.peer, k.class)`; call the REAL `classify_reliable(&mut st, k.incarnation, /*epoch*/ u32::MAX, k.seq)` (the outbox re-frames at `epoch=u32::MAX`, per `framed_row` outbox.rs:929 and the write-path re-stamp); `arrivals += 1`; on `Accept | Reset` → `delivered.insert(k)` (return the insert bool); on `Dedup | Gap | StaleIncarnation | StaleEpoch` → return `false` (dropped, `delivered` unchanged). This is code-under-test: a mutation to `classify_reliable` (e.g. dropping the incarnation reset at mesh.rs:364) makes a post-restart fresh-incarnation `seq0` route through a stale `hw` → `Dedup` instead of `Reset` → `delivered.len()` falls short → RED.

**`CaptureTransport` (block-A+B model, faithful to write_frame).**
`struct CaptureTransport { submitted: Arc<AtomicU64>, durable: Arc<AtomicU64>, lane_alive: bool, fail_after: Option<usize>, sent: Vec<(NodeId, MsgClass, Vec<u8>)> }` (single-threaded proptest → plain fields, no Rc/RefCell needed since the ledger is fed in the assertion phase).
`send_durable(to, class, payload, Retained)`: if `fail_after` reached → return `Err(QueueFull(payload))` (drives LaneStuck/LaneDead — DET-2); else `submitted.fetch_add(1, Release)` (models `submit_barrier` block A, mesh.rs:1723) AND `durable.fetch_add(1, Release)` (models the fsync bumping `last_durable`, store.rs:515) AND `sent.push((to, class, payload.to_vec()))`; return `Ok(MsgId(0))`. `lane_alive(_)` → `self.lane_alive`. Both bumps in one call collapse write_frame's A+B synchronously (confirmed: retain@656 → submit@1723 → wait_durable@1760).

## (2) OP SET + STATE MUTATIONS

`enum Op { Retain{peer, class, seq, payload}, Commit, Ack{idx}, SourceCrash, BootReplay, DestRedeliver{idx} }`. Strategy: `Vec<Op>` len `0..=48` (DET-4). `peer` ∈ {NodeId(1), NodeId(2)} usually, occasionally NodeId(9) off-roster (drives quarantine). `class` ∈ the 7 `MsgClass`. incarnation is NOT a free field — a monotone `Ref.incarnation` counter bumped by SourceCrash. A separate boolean knob per Retain produces a raw-garbage (undecodable) payload occasionally.

Independent reference: `struct Ref { committed: BTreeMap<OutboxKey,Vec<u8>>, staged: BTreeMap<OutboxKey,Option<Vec<u8>>>, incarnation: u64, gc_swept: BTreeSet<OutboxKey>, delivered: BTreeSet<OutboxKey> }`. Ref is maintained BY HAND (never by calling the sink).

- **Retain**: `k = OutboxKey{peer, class, incarnation: Ref.incarnation, seq}`. framed = real `encode_frame(ReliableFrame{from:NodeId(1), class, incarnation:Ref.incarnation, epoch:u32::MAX, seq, bytes:vec![payload]})` (or raw garbage for the undecodable knob). REAL: `sink.retain(&k, &framed)`. MODEL: `Ref.staged.insert(k, Some(framed))`.
- **Commit**: REAL `sink.commit()`. MODEL: drain `Ref.staged`→`Ref.committed` (Some→insert, None→remove), clear staged.
- **Ack{idx}**: pick an existing committed-or-staged key by index (no-op if empty). REAL `sink.release(&k)`. MODEL `Ref.staged.insert(k, None)`.
- **SourceCrash**: rebuild the sink from ONLY its committed map: `sink = ModelOutboxSink{ committed: prev.committed.clone(), staged: empty, durability: fresh }`; mint a fresh `(handle, submitted, durable)` via `fresh_capture_pair()` (INV-8/DET-5) shared by the new sink AND the new CaptureTransport. MODEL: clear `Ref.staged`, `Ref.incarnation += 1`, committed UNCHANGED (RAM lost, disk kept — store.rs:894-907).
- **BootReplay**: REAL `counts = replay_outbox(&shared, &mut capture, &roster)?` (healthy path; error-arm cases use `replay_outbox_with_limits(.., fast_limits())` — DET-2). MODEL: for each committed key in ascending order — off-roster→quarantine (stays committed, `quarantined+=1`); undecodable→quarantine; else→`expected_deliveries.push(k)`, `Ref.gc_swept.insert(k)`, remove from `Ref.committed`. Assert `counts == ReplayCounts{replayed, quarantined}`. Assert **positional** `capture.sent == expected_deliveries.map(|k|(k.peer, k.class, expected_payload(k)))` (MF-2/DET-7) AND `capture.sent.len() as u64 == submitted_after - base` (INV-8) AND `capture.backpressure_stalls-equivalent == 0` via handle (DET-6). Then feed the REAL ledger: `for k in expected_deliveries { ledger.accept(k); Ref.delivered = ledger.delivered.clone(); }`.
- **DestRedeliver{idx}**: pick a key ONLY from `ledger.delivered` (MF-6/INV-6/DET-1 — the only physically-redeliverable set); `assert!(!ledger.accept(k))` (a duplicate must be `Dedup`→false) and `ledger.delivered.len()` unchanged. No sink mutation.

After every op: `assert_eq!(sink.committed, Ref.committed)` AND `assert_eq!(sink.scan_all(), Ref.committed.iter().map(clone).collect::<Vec<_>>())` (INV-5, the independent decode path).

## (4) FENCE-DRIVING (exact wiring)

Per BootReplay: `fresh_capture_pair()` (INV-8/DET-5) calls `controllable()` ONCE, returns `(handle, transport)` sharing ONE `(submitted, durable)` Arc pair; the sink's `durability` field holds the `handle`, the transport holds the same Arcs. `replay_outbox` reads `base = durability().last_submitted()` (outbox.rs:476) = the fresh pair's current value (0 at genesis, or a pre-seeded B). Each routable+decodable send: `submitted.fetch_add(1)` AND `durable.fetch_add(1)`. Count-fence `while last_submitted < base + replayed` (outbox.rs:537) is FALSE on first check → zero sleeps. `wait_durable_through(base + replayed)` (outbox.rs:546) hits `park_until_durable`'s fast-path `last_durable >= target → return` (store.rs:394), `writer_alive` reads true → no death panic, `fsync_backpressure` NOT bumped (store.rs:199, since `last_durable >= seq`). `checked_add` (outbox.rs:532): base finite → no overflow (contrast `already_durable()`'s u64::MAX = C1, outbox.rs:1057-1069, EXCLUDED). Net: synchronous, single-thread, deterministic, zero park, zero backpressure.

Error arms use `replay_outbox_with_limits(.., fast_limits())` (5 retries/50ms, outbox.rs:1102-1108) with `fail_after=Some(k)` (→LaneStuck after k) or `lane_alive=false` (→LaneDead, zero spin, outbox.rs:407-409); assert committed UNCHANGED (gc skipped, outbox.rs:449-452, 515).

## DESIGNER fields

### model
The proptest is a PURE, mock-backed, deterministic reference-model check that drives the REAL `replay_outbox` (crates/io-prod/src/outbox.rs:453) through arbitrary crash/restart/redeliver interleavings and cross-checks the real disk state against a hand-maintained reference model at every step. It has FOUR mutually-referencing pieces; the whole point is that the model is computed from a DIFFERENT source of truth than the code under test, so an agreement assertion is load-bearing.

FILE: a new proptest module gated behind `#[cfg(test)] mod replay_proptest` at the tail of crates/io-prod/src/outbox.rs (NOT tests/ — it needs the crate-private `OutboxKey{..}` constructor, `decode_value_payload`, `MockOutboxSink`, and pub(crate) `ReliableFrame`, exactly like the existing B2 test at outbox.rs:1233). proptest is a workspace dep (Cargo.toml:57) but io-prod does not yet list it — add `proptest = { workspace = true }` under io-prod `[dev-dependencies]` (crates/io-prod/Cargo.toml, currently only `vd-node`). No feature flag: the whole model rides `controllable()` (store.rs:280) + a mock sink, no `store-test-hooks`, so it runs in the default `coverage-io-prod` gate (matching the B2 test's deliberate plain-`#[test]` choice, outbox.rs:1231-1233).

=== (1) THE MODEL OutboxSink — `ModelOutboxSink` ===
Generalizes the existing `MockOutboxSink` (outbox.rs:1032) into a two-set RAM/disk crash-boundary model. Fields:
  - `committed: BTreeMap<OutboxKey, Vec<u8>>` — the DURABLE (survives-crash) set. This is what `scan_all` returns (ASCENDING via BTreeMap, matching NodeOutbox scan order, outbox.rs:255-265).
  - `staged: BTreeMap<OutboxKey, Option<Vec<u8>>>` — the RAM window: `Some(framed)` = a staged retain, `None` = a staged release/delete. Lost on SourceCrash. Mirrors RedbStore's `staged: Batch` semantics (store.rs:68, put=Some, delete=None) EXACTLY.
  - `durability: DurabilityHandle` — a `controllable()` handle (store.rs:280) shared with the capture transport.
Trait impl (each method mirrors NodeOutbox, outbox.rs:237-300):
  - `retain(k, framed)` → `staged.insert(k, Some(encode-strip-form))`. Store the ALREADY-envelope-stripped framed bytes (what `scan_all` yields), so no version byte bookkeeping in the model.
  - `release(k)` → `staged.insert(k, None)`.
  - `commit()` → drain `staged` into `committed` last-write-wins: `Some(v)`→insert, `None`→remove. Clears `staged`. (Models the off-tick fsync making the batch durable.)
  - `scan_all()` → `committed.iter().map(clone).collect()` — ASCENDING, envelope already stripped (contract at outbox.rs:176-178).
  - `gc_below(inc)` → retain committed keys with `key.incarnation >= inc` (unused by replay; kept for trait completeness, outbox.rs:186).
  - `gc_replayed(keys)` → `for k in keys { committed.remove(k); }` — EXACTLY the re-driven keys, straight-line delete, byte-identical to NodeOutbox (outbox.rs:281-287) and the real MockOutboxSink retain-filter (outbox.rs:1044).
  - `submit_barrier()` → `if staged.is_empty() { None } else { Some((next_seq, durability.clone())) }` (only touched if the proptest ever wires the mesh block A; replay itself never calls it — replay only calls scan_all/durability/gc_replayed/commit).
  - `durability()` → `durability.clone()`.

=== (2) THE RECEIVER DEDUP LEDGER — `DedupLedger` ===
A standalone `struct DedupLedger { seen: BTreeSet<OutboxKey>, deliveries: usize }`. This is the END-TO-END exactly-once oracle: it models the FAR-END receiver's `classify_reliable` dedup, keyed on the FULL `OutboxKey` tuple `(peer, class, incarnation, seq)` — the SAME identity the doc-comment at outbox.rs:100-103 says makes a replay idempotent ("the SAME tuple the receiver dedups on"). `fn accept(&mut self, k: OutboxKey) -> bool { self.deliveries += 1; self.seen.insert(k) }` returns `true` iff FIRST delivery (a genuine new effect), `false` iff a DUPLICATE the receiver drops. `deliveries` counts EVERY arrival (incl. dups); `seen.len()` counts distinct effects. The exactly-once invariant is `seen.len()` == number of distinct committed keys ever produced, regardless of how many times replay re-delivered them.

=== (3) THE CAPTURE TRANSPORT — `CaptureTransport` ===
A `ReplayTransport` (the supertrait at mesh.rs:1938) that faithfully MODELS the mesh block-A re-mirror + block-B fsync (mesh.rs behaviour the prompt names) AND feeds the dedup ledger. Fields:
  - `submitted: Arc<AtomicU64>`, `durable: Arc<AtomicU64>` — the SAME two atomics `controllable()` handed back (store.rs:292), shared with the sink's handle.
  - `ledger: Rc<RefCell<DedupLedger>>` (single-threaded proptest → Rc/RefCell; the whole proptest runs on ONE thread, no bg thread, unlike the B2 test).
  - `lane_alive: bool` (default true), plus optional `fail_after: Option<usize>` to inject a LaneDead/LaneStuck after k sends (for the error-arm interleavings).
  - decode: on `send_durable(to,class,payload,Retained)` it reconstructs the OutboxKey — BUT the payload alone lacks incarnation/seq. So the transport carries a side-channel: replay iterates rows in key order and calls send in that order; the CaptureTransport instead keys the ledger on a monotone per-(peer,class) counter it maintains... NO — cleaner: the transport does NOT reconstruct the key. Instead `send_durable` does THREE things modeling the fresh-incarnation re-mirror synchronously: (a) `submitted.fetch_add(1, Release)` (block A submit — drives the count-fence, exactly the RemirrorTransport at outbox.rs:1251); (b) `durable.fetch_add(1, Release)` (block-A submit + the fsync BOTH, per the prompt's fence-driving spec: "submitted += 1 AND durable += 1"); (c) record the delivered payload into a `Vec<(NodeId,MsgClass,Vec<u8>)> sent` list. The dedup-ledger accept happens in the ASSERTION phase, not inside the transport — see fence_driving. This keeps the transport a faithful, deterministic block-A+B model with NO thread and NO fsync.

=== (4) OP SET (proptest strategy: `Vec<Op>`, 0..=64 ops) ===
`enum Op { Retain{peer:0..3, class:idx 0..7, seq:0..4, payload:u8}, Commit, Ack{idx}, SourceCrash, BootReplay, DestRedeliver{idx} }`. Peers drawn from a fixed roster {NodeId(1),NodeId(2)} PLUS an occasional off-roster NodeId(9) (drives the QUARANTINE arm). incarnation is NOT a free op field — it is a monotone counter bumped by SourceCrash (a crash = a restart at a fresh incarnation), so every post-crash Retain lands at a higher incarnation, exactly modeling the fresh-incarnation re-mirror (outbox.rs:422-423). See ops field for how each mutates real+model state.

### ops
Each Op mutates BOTH the real `ModelOutboxSink` (behind `SharedOutbox`) — wait: the ModelOutboxSink IS the code-under-test's sink, so "real state" = the sink's committed/staged maps as the CODE mutates them via the trait; "model state" = a SEPARATE plain reference struct `Ref { committed: BTreeMap<OutboxKey,Vec<u8>>, staged: BTreeMap<OutboxKey,Option<Vec<u8>>>, incarnation: u64, gc_swept: BTreeSet<OutboxKey>, produced: BTreeSet<OutboxKey> }` the harness maintains by hand. The check is `sink.committed == Ref.committed` after every op — two independent computations of the same set. This is the anti-vacuity core: the Ref is NOT computed by calling the sink.

- Retain{peer,class,seq,payload}: key = OutboxKey{peer, class, incarnation: Ref.incarnation, seq}. framed = a REAL `encode_frame(ReliableFrame{from:local, class, incarnation, epoch:u32::MAX, seq, bytes:vec![payload]})` (outbox.rs:922-932 `framed_row` generalized) so `decode_value_payload` (outbox.rs:382) recovers `[payload]` — an UNDECODABLE variant is a separate op-free knob (a raw-garbage payload, drives the undecodable-quarantine arm). REAL: `sink.retain(&key, &framed)`. MODEL: `Ref.staged.insert(key, Some(framed))`, `Ref.produced.insert(key)`.
- Commit: REAL `sink.commit()`. MODEL: drain `Ref.staged` into `Ref.committed` (Some→insert, None→remove), clear staged.
- Ack{idx}: pick an existing committed-or-staged key by index (or no-op if empty). REAL `sink.release(&key)`. MODEL: `Ref.staged.insert(key, None)`. (Ack = the far end acked ⇒ retire the retained row; a staged release, durable at next Commit.)
- SourceCrash: models the SOURCE shard process dying. REAL: DISCARD the sink's `staged` map WITHOUT committing (crash before fsync) — the harness rebuilds the sink from ONLY its `committed` map: `let sink = ModelOutboxSink{ committed: prev.committed.clone(), staged: empty, durability: fresh controllable() }`. A FRESH `controllable()` handle+atomics+capture-transport are minted (a restarted process has base counters at 0 again — the new incarnation's watermark). MODEL: clear `Ref.staged` (RAM lost), `Ref.incarnation += 1` (restart bumps the process-epoch). committed UNCHANGED (survives the crash — THE RAM-vs-disk boundary, prompt's load-bearing fidelity: staged-not-committed CLEARED, committed KEPT).
- BootReplay: the headline op. REAL: `let counts = replay_outbox(&shared, &mut capture, &roster)?`. This snapshots committed rows, sends each decodable+routable one via capture.send_durable (submitted+=1, durable+=1), count-fences (passes synchronously — see fence_driving), then gc_replayed the re-driven keys + commit. MODEL: compute the EXPECTED disposition by hand: for each committed key k in ASCENDING order — if `!roster.contains(k.peer)` → expect QUARANTINE (stays in Ref.committed, quarantined_count+=1); else if payload undecodable → QUARANTINE; else → REPLAYED: `expected_deliveries.push(k)`, `Ref.gc_swept.insert(k)`, remove from Ref.committed. Assert `counts == ReplayCounts{replayed: expected_replayed, quarantined: expected_quarantined}`. Then FEED the dedup ledger: for each replayed k, `ledger.accept(k)` — a re-delivery of an already-seen key returns false (a correctly-deduped duplicate).
- DestRedeliver{idx}: models the DEST receiving a row AGAIN out of band (the transport redelivered a frame the source already got acked, or a duplicate arrival) — pick a key from `Ref.produced` and `ledger.accept(k)` directly (no sink mutation). This is what exercises the dedup ledger's DUPLICATE path independently of replay: it must return false and NOT bump seen.len() beyond distinct-produced.

AFTER-EVERY-OP assertion: `assert_eq!(sink.committed, Ref.committed)` — the running no-loss/no-orphan cross-check. AFTER the WHOLE sequence: the four terminal invariants (below).

### invariants
All four are checkable predicates over (Ref.committed = the committed set, ledger = the dedup ledger, Ref.gc_swept = the swept set, Ref.produced = every key ever staged). Stated so each is neither vacuous (a broken impl fails it) nor falsely-red (a correct impl passes it).

INV-1 NO-LOSS (committed rows are never dropped except by a real replay/ack): after every op, `sink.committed == Ref.committed`. Predicate: every key that was COMMITTED and not yet (replayed+durable-gc'd) or (released+committed) is STILL in sink.committed. NON-VACUOUS: a mutant that gc's a quarantined row (the pre-F1 `gc_below` blunt sweep, outbox.rs:191-193) drops a roster-gone committed key ⇒ sink.committed loses it ⇒ `!=` Ref.committed ⇒ RED. NON-FALSELY-RED: a STAGED-not-committed row lost to SourceCrash is CORRECT loss — the Ref ALSO clears staged on crash and never promotes it, so both sides agree (the prompt's "staged row lost to a crash is CORRECT loss, not a defect"). The invariant is stated over COMMITTED only, precisely.

INV-2 NO-ORPHAN (gc sweeps ONLY re-driven keys; every non-committed key is explained): `Ref.gc_swept ∩ Ref.committed == ∅` AND `Ref.gc_swept ⊆ {keys that were replayed with a routable+decodable frame}`. Predicate: a key leaves committed ONLY via (a) release+commit (ack path) or (b) replayed+durable gc — never spontaneously. NON-VACUOUS: a mutant that gc's BEFORE the durability fence (moving gc_replayed above wait_durable_through — the exact D-6 #1 mutation the B2 test guards, outbox.rs:1225-1230) would, in an interleaving where BootReplay is followed by inspection, sweep a key whose fresh copy is not durable; but in this SYNCHRONOUS model durable+=1 happens in send, so instead the guard is: gc_swept keys must ALL be in expected_deliveries — a mutant that swept a quarantined key puts a non-replayed key in gc_swept ⇒ predicate false ⇒ RED. NON-FALSELY-RED: the ack path legitimately removes committed keys, and those are NOT in gc_swept (they went via release), so the ⊆ holds for a correct impl.

INV-3 NO-DOUBLE-COUNT / EXACTLY-ONCE (the dedup ledger): at end, `ledger.seen.len()` == count of DISTINCT keys that were ever replayed-or-redelivered, AND `ledger.seen == Ref-expected-delivered-set`. Predicate: no matter how many BootReplay + DestRedeliver ops re-drove a key, it produced EXACTLY ONE distinct effect (`seen.insert` returned true exactly once per key). NON-VACUOUS: a mutant receiver that dedups on a PARTIAL key (drops incarnation — e.g. keys on (peer,class,seq) only) would MERGE a pre-crash key and its post-crash-fresh-incarnation twin into one, so a genuinely-new post-restart row is falsely deduped ⇒ seen.len() < distinct-produced ⇒ RED; conversely a mutant that dedups on nothing (always-accept) gives seen incremented per arrival, and DestRedeliver of an already-seen key would push seen beyond distinct ⇒ `ledger.deliveries > ledger.seen.len()` is EXPECTED but `seen.len()` must equal distinct-delivered — a no-dedup mutant makes seen a multiset-sized value ⇒ RED. NON-FALSELY-RED: a correct impl accepts each distinct OutboxKey once; duplicates return false and never grow seen.

INV-4 REPLAYED+QUARANTINED ACCOUNTING (RC-2a no-silent-loss, outbox.rs:369-377): for EVERY BootReplay, `counts.replayed + counts.quarantined == number of committed rows scanned at that boot` AND `counts.replayed == |expected_deliveries|` AND `counts.quarantined == |roster-gone| + |undecodable|`. Predicate: every retained row at boot is EITHER re-driven+gc'd OR quarantined+retained — none silently vanishes. NON-VACUOUS: a mutant that `continue`s on a decode failure WITHOUT `counts.quarantined += 1` (outbox.rs:512) makes replayed+quarantined < scanned ⇒ RED. NON-FALSELY-RED: the exact arms at outbox.rs:500/512/517 produce this partition for a correct impl. This is the invariant that makes INV-1's "except by a real replay" precise — the accounting IS the explanation.

### fence_driving
EXACT wiring so `replay_outbox` completes each BootReplay SYNCHRONOUSLY + deterministically, no thread, no fsync (contrast the B2 test at outbox.rs:1233 which uses a bg thread precisely because its RemirrorTransport bumps ONLY submitted and parks the fence). Here we want NO park:

1. Per BootReplay, the harness holds the sink's `controllable()` handle and its two atomics `(submitted, durable)` (store.rs:280-293) — the SAME `Arc<AtomicU64>`s the CaptureTransport was constructed with. Because both the sink's `durability` field AND the transport hold clones of the SAME Arcs, a transport bump is visible to `replay_outbox`'s `durability.last_submitted()` / `wait_durable_through`.

2. `replay_outbox` reads `base = durability().last_submitted()` (outbox.rs:476) — for a fresh `controllable()` this is 0 (NOT u64::MAX; u64::MAX is `already_durable()`, the C1 overflow arm the prompt excludes, outbox.rs:1063). After a SourceCrash mints a fresh handle, base resets to 0 (a restarted process) OR, to model a process that already did real submits pre-crash, the harness may pre-seed submitted=durable=B; either way base is finite and small.

3. For each routable+decodable row, `replay_outbox` calls `capture.send_durable(peer,class,payload,Retained)`. The CaptureTransport does BOTH bumps atomically: `submitted.fetch_add(1, Release)` (models mesh block-A retain+submit_barrier, mesh.rs) AND `durable.fetch_add(1, Release)` (models the fsync completing). This is the prompt's spec verbatim: "submitted += 1 AND durable += 1, modeling block A submit + the fsync".

4. The count-fence `while durability.last_submitted() < base + replayed` (outbox.rs:537): after N sends, submitted == base+N == target, so the loop condition is FALSE on first check ⇒ passes with ZERO `sleep` iterations, synchronously, on the calling thread.

5. `wait_durable_through(base + replayed)` (outbox.rs:546): last_durable == base+N >= target, so `park_until_durable`'s fast-path returns immediately (store.rs:394) — no condvar, no thread. `writer_alive` reads true (controllable default, store.rs:289) so no death panic.

6. `checked_add(counts.replayed)` (outbox.rs:532): base is finite+small ⇒ no overflow (contrast already_durable's u64::MAX). Then the gc_replayed+commit runs under the brief lock (outbox.rs:551-555), synchronously mutating the ModelOutboxSink's committed map.

Net: BootReplay returns synchronously in the proptest's single thread, deterministically, with committed mutated exactly as the Ref predicts. The LaneStuck/LaneDead error-arm interleavings use CaptureTransport.fail_after/lane_alive to make send_durable_with_retry `?`-bail (outbox.rs:515), and the harness asserts committed is UNCHANGED (gc skipped, outbox.rs:449-452) — the refuse-to-boot no-loss path.

### anti_vacuity
MIN-HIT ASSERTIONS (the coverage floor that proves the arbitrary sequences actually EXERCISE the hard paths, not just trivially-empty runs). The strategy alone does not guarantee an interesting interleaving, so the module ALSO carries three explicit non-proptest `#[test]` witnesses AND a proptest-internal coverage counter (a `Cell<Coverage>` the harness bumps and asserts non-zero via `proptest`'s success-count aggregation is not directly available, so instead PIN each as a standalone deterministic hand-written case that MUST hit the arm):

MIN-HIT-1 (>=1 SourceCrash-with-staged): a hand-written `#[test] source_crash_drops_staged_keeps_committed` — Retain k1, Commit, Retain k2 (staged, uncommitted), SourceCrash. Assert sink.committed == {k1} (k2's staged retain LOST), Ref agrees. Proves the RAM-vs-disk boundary is actually taken with a non-empty staged set (a crash with EMPTY staged would be vacuous).

MIN-HIT-2 (>=1 BootReplay-after-crash that re-drives): hand-written `#[test] boot_replay_after_crash_redrives_and_gcs` — Retain k@inc0, Commit, SourceCrash (inc→1), BootReplay. Assert counts.replayed==1, committed empty after (gc'd), ledger.seen=={k}, and a SECOND BootReplay returns replayed==0 (idempotent — nothing left). Proves the headline path end-to-end.

MIN-HIT-3 (>=1 DestRedeliver of a delivered row): hand-written `#[test] redeliver_is_deduped` — Retain k, Commit, BootReplay (ledger accepts k, true), DestRedeliver k. Assert the DestRedeliver's `ledger.accept(k)` returned FALSE and ledger.seen.len() stayed 1 while ledger.deliveries==2. Proves exactly-once under a genuine duplicate.

CRASH-MID-REPLAY REGRESSION (hand-written, the sharpest): `#[test] crash_mid_replay_loses_nothing` — Retain k1@inc0, Retain k2@inc0, Commit (both durable). BootReplay with a CaptureTransport whose `fail_after=Some(1)` so it re-drives k1 (submitted/durable→1) then returns LaneStuck on k2 (outbox.rs:415). Assert `replay_outbox` returns `Err(LaneStuck{peer})`, the `?` bailed BEFORE the fence/gc (outbox.rs:515), and BOTH k1 AND k2 are STILL in committed (gc skipped ⇒ no partial sweep — the row k1 that DID re-drive is NOT gc'd because gc_replayed only runs after the fence, which the `?` skipped). Then a FRESH BootReplay (transport healthy) re-drives BOTH: assert replayed==2, ledger.seen=={k1,k2} (k1 delivered twice across the two boots but deduped to ONE effect — exactly-once survives a crash-mid-replay). This is the case that proves the refuse-to-boot-skips-gc invariant (outbox.rs:449-452) composes with dedup to give no-loss AND exactly-once even when the FIRST replay dies partway.

PINNED SEED: the proptest carries `#![proptest_config(ProptestConfig{ cases: 4096, .. })]` and the module pins one regression seed via `proptest!`'s persistence file `crates/io-prod/proptest-regressions/outbox.txt` seeded with a captured shrink of a SourceCrash+BootReplay+DestRedeliver interleaving. For the coverage RUN, pin `PROPTEST_CASES=4096` and a fixed RNG seed by adding `.rng(TestRng::from_seed(RngAlgorithm::ChaCha, &[0x6d;32]))` in a dedicated `#[test] replay_model_pinned_seed` wrapper so CI reproduces the exact interleaving distribution (proptest default seeding is entropy-based, non-deterministic across runs — the pinned ChaCha seed [0x6d;32] makes the coverage run byte-reproducible).

### open_questions
- API-INSUFFICIENCY (payload→key reconstruction): `replay_outbox` calls `transport.send_durable(peer, class, PAYLOAD, Retained)` — it passes the decoded PAYLOAD, NOT the full OutboxKey (outbox.rs:515, and decode_value_payload strips the frame header at outbox.rs:382). So the CaptureTransport CANNOT reconstruct the (incarnation, seq) to key the dedup ledger from the send args alone — it only sees (peer, class, payload). RESOLUTION used in this design: the harness does NOT feed the ledger from inside the transport; it feeds it in the assertion phase from the Ref's expected_deliveries (which knows the full keys, in the same ascending scan order replay uses). This is sound but means the ledger check is one step removed from the actual send. A tighter alternative would need replay to re-send the STORED FRAME (which carries incarnation/seq) instead of the re-framed payload — but that is deliberately NOT done (outbox.rs:379-386 re-frames at the fresh incarnation), so the design's assertion-phase feed is the correct model. Flag for the implementer: make the ascending-order correspondence explicit (assert capture.sent.len() == expected_deliveries.len() and payloads match positionally) so the two orderings are pinned to agree.
- Should the proptest also model the FAR-END receiver's incarnation-reset (classify_reliable Reset-then-Accept, outbox.rs:422-423) as a ledger op, or is keying the dedup on the full OutboxKey (which includes incarnation) a sufficient model of the reset? Current design assumes full-key dedup subsumes the reset (a fresh incarnation = fresh keys = never deduped against the old incarnation), which matches the doc-comment at outbox.rs:100-103 — but a real receiver RESETS its high-water on a higher incarnation rather than keeping an unbounded seen-set.
