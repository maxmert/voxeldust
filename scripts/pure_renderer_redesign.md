# Pure-Renderer Client Redesign — vetted design (workflow wf_a558e80d)

## Recommendation
GO_WITH_FIXES — but honestly scoped as a FOUNDATIONAL INVERSION of the client-facing protocol, not a refactor. This deletes an entire protocol subsystem (D-36 client-confirmation watermark, AuthorityChanged/RequestCut/CutConfirmed disambiguation) and re-keys the client's core data model (tracks (SubId,EntityId)->EntityId) across THREE lockstep protocol consumers, with TWO frozen-wire minor bumps (2 and 3) and a genuine emit-path change (entity_fence onto EntitySnap) plus two gateway hot-path byte-helper changes the original proposal missed. The architectural direction is SOUND and the adversary's is_sound:false is about UNDER-SPECIFICATION, not a dead end — every must-fix has a concrete resolution folded above. \n\nHARD PRECONDITION: S1 (input-cut design spike) MUST resolve before the client collapse — the 'client stamps nothing' input cut is refuted by the code as stated, and is the one place the target architecture is currently unimplementable. Recommend accepting a client-stamped cut seq as the honest default (the client legitimately owns 'which input was my last pre-handoff action') unless the gateway handoff-tick->seq correlation proves cheap. \n\nEFFORT: this is a multi-week, ~11-slice arc touching wire/sim/node/connection-plane/client/harness/bins/devproto + docs, every slice always-green and independently mergeable, with 3 new proptests (fence monotonicity across the outcome matrix, input-conservation across the cut, no-vanish under loss) and the HR4 non-vacuity work (StationLocal composition). It does NOT fix D-9 scale or nested multi-mesh — those stay ledgered to P6/P8. Do NOT undersell it as 'the client just renders' — the render side is genuinely already EntityId-keyed and unchanged, but the protocol/authority/input/interp surface beneath it is being rebuilt.

## Final architecture
THE PURE-RENDERER ARCHITECTURE (final, adversary-hardened). The client collapses to: receive BE-opened subs -> render every entity at its global coordinate -> forward move signals. The unifying insight is a DRY consolidation, not a new system: the current protocol carries per-(SubId,EntityId) authority-disambiguation machinery (view.rs:39 keyed tracks, authoritative_sub view.rs:43, set_authority view.rs:97, chosen_subs view.rs:144) whose ONLY purpose is to de-dup an entity the SERVER chose to emit twice (emits() = simulates()|is_fed_ghost|is_retained_ghost, stub.rs:3680). Send the entity ONCE (in its authoritative realm) and that whole parallel machinery collapses onto the ONE primitive that already governs transfer: the per-entity Fence (is_stale_against, fence.rs:43 — the SAME comparator the gateway fan-out already uses at gateway.rs:1921).\n\nCLIENT MODEL. Re-key DeliveredView.tracks -> EntityId (one track per entity, latest-wins via the existing EntityTrack::observe, interp.rs:88). held_subs STAYS A SET (net.rs:250) — multi-realm AoI legitimately holds many subs (a player in a ship docked at a station on a planet holds Ship+Station+Planet+System subs at once); what is deleted is per-entity authority disambiguation, not multi-sub holding. The Bevy renderer is UNCHANGED (already EntityId-keyed).\n\nORDERING KEY (load-bearing, adversary-pinned). universe_tick alone cannot order two copies of one entity at the handoff tick (both realms emit it at the same tick in different frames; interp.rs:97-103 treats equal-tick in-place, so arrival ORDER would decide — non-deterministic). The sound reject key is dot.entity_fence (the DirectoryKey::Entity CAS fence, stub.rs:161) — NOT the realm fence (D-25: non-comparable domains, mixing = black screen). EntityTrack.last_fence rejects incoming.fence.is_stale_against(last_fence); the dest's post-CAS entity_fence strictly exceeds the retained source ghost's OLD entity_fence (which intentionally diverges, stub.rs:157-161), so the dest wins the overlap DETERMINISTICALLY regardless of arrival order. This must be PROVEN monotone across source->dest AND across an A->B->A flap (existing anti-flap is geometry-level: OverlapBand dwell + should_commit strict rising edge, so the saga does not re-fire per tick, but a double-commit's two entity_fence bumps must be strictly increasing at the entity key).\n\nSERVER-ORDERED HANDOFF (D-36 deleted). The handoff is ALREADY server-ordered (Committed->Demote->DemoteAck->Promote, source sub held across overlap; promote_apply flips dest Ghost->Owned + announces SubscriptionReady BEFORE source stops, stub.rs:1782+). Gate ReleaseSubscribe on promote_acked ALONE (saga.rs:1317), deleting the D-36 client-confirmation watermark (recompute_delivery_watermarks + Session.delivered + DeliveredToObservers). The dest is live-before-source-close BY CONSTRUCTION (server-ordered acks + coordinate-driven CAS commit tick), never by a client confirmation. NO-VANISH BACKSTOP (adversary must-fix): because Releasing no longer waits on delivery, add a SERVER-TIMED hold of K ticks on the source client-emit post-promote (NOT client-confirmed — does not re-introduce D-36) so the source keeps self-emitting until the dest's first frame has had K ticks to land; clean source-copy removal then rides a NEW reliable EventMsg::EntityRemoved client arm (which does NOT exist today, net.rs:177/view.rs:20-23), ordered AFTER the dest's first Owned frame.\n\nSEND-ONCE (HR1 split). Filter the CLIENT emit to simulates() alone (stub.rs:3721); KEEP the retained/fed ghost as the cross-shard COLLIDER (feed_source_ghosts stub.rs:3580, InterShardFlow::Ghost) — players still physically collide across the seam. Only the client render-emit is cut.\n\nINPUT CUT (UNRESOLVED — see residual risks). The client stamps nothing is the TARGET, but the proposal's server-side seq pivot is refuted by the code (last_input_seq is the observed high-water, not the intended cut seq, gateway.rs:1470-1476). Sound options: (a) keep a client-stamped cut seq (the one fact only the client knows — which input it generated before it saw the handoff), OR (b) build+prove a NEW gateway per-session handoff-tick->seq correlation with input-conservation. This is the single hardest open item and must be designed before the client-collapse slice lands.\n\nINTERP CONTINUITY. observe() collapses the window and freezes on a frame change (interp.rs:89-96); across a realm handoff the dest is a different FrameRef. The continuity fix (re-express prev into the dest frame so the handoff is sub-frame-smooth) MUST be a PURE exact-integer LatticePos rebase of the FROZEN prev sample (D-41 cell+offset), NEVER a re-projection through world_pos's live hull pose (view.rs:239) — else it becomes client-side prediction. It must land WITH the collapse (a mass stutter at hundreds-crossing otherwise) and share the D-41 cross-cell seam (interp.rs:113-117).\n\nMULTI-MESH (honestly scoped). world_pos (view.rs:227-243) composites ShipLocal through the hull's live pose but returns IDENTITY for StationLocal AND AreaLocal (view.rs:238) — so a ship docked IN a station renders at the station frame origin, uncomposed. The 3-deep nest (ship-in-station-on-planet) is NOT rendered correctly today, and D-35 version-matching (view.rs:219-225) is deferred. The pure-renderer collapse does NOT claim nested multi-mesh works; HR4's >=2-realm fixture is vacuous unless it runs on non-identity realms (Ship/Station), so StationLocal composition must be built for the fixture to be meaningful there.

## Residual risks
- INPUT-CUT is the single unresolved architectural item. 'Client stamps nothing' is NOT achievable without either re-introducing a client-stamped cut seq (the ONE fact only the client owns) or building+proving a NEW gateway handoff-tick->seq correlation with input-conservation. Until S1 locks this, the pure-renderer's 'zero client decisions' goal is aspirational for input specifically. Verified: gateway.rs:1470-1476 refutes the proposed last_input_seq pivot.
- FENCE MONOTONICITY across abort/re-home/flap is asserted-necessary but not yet proven. The dest entity_fence > retained-source entity_fence works today by construction (stub.rs:157-161) but the design must add a proptest over the full transfer-outcome matrix (happy, abort mid-transfer, D-37 re-home to a third shard, A->B->A flap within the interp buffer) or a false-stale black screen can slip in.
- MULTI-MESH NESTING is genuinely broken today for non-identity realms (world_pos returns identity for StationLocal/AreaLocal, view.rs:238). D-35 version-matching (view.rs:219-225) means hull+interior on different lossy subs can jump under loss. The pure renderer does not fix either; the 3-deep ship-in-station-on-planet is not rendered correctly. HR4's parity is vacuous until StationLocal composition (S9) exists.
- D-9 is NOT fixed. emit_frames still broadcasts the WHOLE realm entity set to every subscriber, MTU-partitioned only (stub.rs:3713-3731), fanned per-subscribed-shard (gateway.rs:1892) — O(entities x clients) at hundreds-in-one-location. Send-once removes a constant multiplier (the double-send) but NOT the O(N*M) wall. AoI sub-opening-by-coordinate (target #3) is not built (InterestZones reader is write-only). The pure renderer is a PRECONDITION for the P6 AoI reshape, not the reshape.
- M-minor3 fence-on-every-overlap-frame adds ~8 bytes/entity during EVERY crossing; at hundreds-crossing-together the overlap windows overlap, spiking bandwidth on the already-MTU-pressured unreliable datagram (CONSERVATIVE_DATAGRAM_BUDGET=1200, channels.rs:202) exactly at the worst moment. - The no-vanish K-tick server-timed hold re-introduces a bounded timing coupling (not a client dependency, but a magic-ish K). K must be config-derived (never an inline literal, per the no-magic-numbers rule) and proven to bound the vanish window under the worst modeled loss without stranding the source emit indefinitely.
- PvP action routing across the cut is unaddressed: fire-registration rides action_bits on the UNRELIABLE input datagram (channels.rs:131-135, D-39.1 owed reliable arm); a shot fired pre-handoff but seq>marker routes to the dest realm which may lack the target's collider in-frame. Out of scope for the pure renderer but a real hole the input cut interacts with.
- HR5 phantom-coverage risk: the SnapshotFrame V1/V2 decoder + the skip-discriminant byte helpers must be exercised per-monomorphization AND in every test binary (process_parity.rs, dev_cluster_smoke.rs, harness) or coverage phantom-drops (the llvm-per-mono gotcha). Keep V1/V2 branchless shims delegating to monomorphic helpers; fence reject via expect on stale/equal/newer, never assert!(matches!).
